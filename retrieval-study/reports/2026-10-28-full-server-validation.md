## 本机兼容问题

本机为 Ubuntu 26.04 / glibc 2.43，上游固定版本 CI 默认使用 Ubuntu 22.04。Docker 已安装，但当前账号不能访问其服务，非交互 sudo 需要管理员认证。本轮没有修改系统权限或使用管理员密码。

沿用已有 GCC 10.3 / Bazel 6.2.0 及依赖缓存继续构建。glibc 2.43 对开启相应特性的 `bsearch`、`memchr` 等调用保留输入的 `const` 限定，旧 elfutils 0.191 的接收变量因此编译失败。依据本机头文件与 [glibc 2.43 公告](https://sourceware.org/pipermail/libc-announce/2026/000052.html)定位了这一问题。

`bench/prepare_build_compat.py` 对固定 elfutils 源文件核验原始 SHA-256，只给只读查找结果增加 `const`，不禁用警告，不修改检索算法。补丁保存在 `patches/build-compat/`，文件前后哈希保存在 `manifests/build-compatibility.json`。原版与候选版必须使用同一份修正后的依赖。它是本机构建兼容配置，不计作个人检索核心优化成果，也不声称构建环境与 Ubuntu 22.04 CI 完全相同。

前两次兼容构建在后续源文件遇到同类错误，失败 manifest 和日志分别保留在 `v31-baseline-compat-20261028`、`v31-baseline-compat2-20261028`。第三次构建通过了全部编译与链接，形成 `builds/v31-baseline-compat3-20261028/typesense-server`。原版保存后才应用候选补丁，形成 `builds/v31-candidate-compat3-20261028/typesense-server`。

`bench/build_server.py` 增加了兼容依赖的构建前后哈希核对，以及服务器 / 测试目标选择。只有固定源码和共同依赖前后均一致，且构建成功，才复制二进制并记录其 SHA-256。

## 真实请求验证准备

已有 `validate_service.py` / `compare_service.py` 已用于同一 v31 的原版与补丁版，涵盖普通查询、过滤、候选限制、分页、排序、精选隐藏、更新删除、重插、截止与恢复。此前 30.2 的同版本重复结果不作为补丁验证。

`bench/build_linked_art_tests.py` 读取成功服务的真实 ART 编译参数和链接参数，复用所有生产链接输入，只替换服务主程序并加入上游 ART 测试、新回归、GoogleTest 及上游测试辅助文件。没有移除过滤实现。测试以生产编译配置执行，属于聚焦集成测试，不是完整 `typesense-test`，也不是整服 sanitizer 构建。

原版与候选结果为 `raw/v31-linked-{baseline,candidate}-tests-20261028.json`；服务差分为 `raw/service-v31-patch-diff-20261028.json`；查询矩阵差分为 `raw/v31-query-matrix-diff-20261028.json`。参数、版本、请求完整性、ID、顺序、计数、分组、facet 和截止状态均按各工具的范围检查。

新增 `bench/validate_deadline_service.py`，通过 API 导入高低分 sibling、删除每组的高分文档，核对删除数量和全量导出摘要，再测试短截止、充足预算对照和精确查询恢复。每次运行拥有自己的回环服务进程与数据目录。

在官方 30.2 上以 2,048 组数据执行工具自检：6,144 条导入，删除 2,048 条，剩余 4,096 条内容核对一致，11 次查询检查通过。该轮与后台编译共机，仅验证工具流程，不报告性能收益或分位数。

## 完整服务中的截止诊断

原版和候选分别导入 98,304 条文档，删除 32,768 条高分 sibling，剩余 65,536 条低分文档的导出摘要均与生成器相符。查询相同前缀，测试无过滤 / 目标过滤、1/2/5/20ms 与充足预算，并在每轮后运行精确查询恢复控制。

下表是每个用例每版 5 个客户端响应样本的中位数，包含 HTTP 传输成本。两版的 1ms 用例均明确返回截止 / 408；区别是内部遍历响应截止条件的及时程度。

| 用例 | 原版响应中位数 | 候选响应中位数 |
| --- | ---: | ---: |
| 无过滤，1ms 预算 | 8.471ms | 1.643ms |
| 目标过滤，1ms 预算 | 7.601ms | 1.596ms |
| 无过滤，充足预算 | 7.636ms | 7.576ms |
| 目标过滤，充足预算 | 18.125ms | 17.381ms |

这些是机制诊断样本，不是正式交替性能实验，未据此报告稳定提升比例、P99、吞吐或严格的毫秒上界。充足预算下的全部控制与恢复结果一致；有限预算允许不同部分结果，必须明确标示截止。对照工具还会检查未截止的有限预算响应与各自充足预算结果一致。

原始记录保存在 `raw/deadline-v31-{baseline,candidate}-20261028/`，对照为 `raw/deadline-v31-patch-diff-20261028.json`。
